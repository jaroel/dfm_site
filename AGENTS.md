# AGENTS.md

Agent-facing map for this repo. Human quickstart lives in `README.md`.

## Stack

- Solid 2 stable (`solid-js`, `@solidjs/web`, `@solidjs/router`, `@solidjs/meta`)
- Start mode via `@solidjs/vite-plugin` + `filesystem-routing`
- Vite 8, Tailwind 4, Vitest 5 with happy-dom, oxlint + oxfmt, Bun 1.4.4+
- Bun only. Do not use npm or pnpm.
- `~/*` aliases `src/*` in apps, tests, and both TypeScript programs.

Before changing Solid code, load the Solid skills in `node_modules/solid-js/skills/`
when present: `solid-2.0`, `solid-2.0-cheatsheet`, `reactivity-diagnostics`.

## Commands

```bash
bun run dev          # Vite dev server
bun run build        # vite build + prerender -> dist/client + dist/server/server.js
bun run start        # bun server.bun.ts (needs dist + node_modules)
bun run preview      # Vite preview of the build
bun run test         # vitest (happy-dom)
bun run lint         # oxlint
bun run typecheck    # bun check for the server and tsconfig.client.json
bun run format       # oxfmt
bun run format:check # fail if formatting is stale
```

## Routes

| URL | File |
|---|---|
| `/` | `src/routes/(home).tsx` (prerendered to static HTML) |
| `/uzg/` | `src/routes/uzg/(uzg).tsx` |
| `/uzg/:file_name` | `src/routes/uzg/[file_name].ts` (GET audio stream, range requests) |
| `/*404` | `src/routes/[...404].tsx` |

`file-routes.d.ts` is generated by `fileRoutes({ types: true })` in `vite.config.ts`.
Do not edit it by hand. `src/router.ts` feeds the generated page routes to the
router; `src/App.tsx` supplies the shared shell and metadata.

## Data flow

```text
src/ftp.ts            raw FTP listing + download, server-only
  -> src/uzg.ts         fetchUzgListing ("use server"), cached listing
  -> src/recordings.ts  filename parsing, formatting, grouping (client-safe)
       src/groupby.ts   Map.groupBy with an older-browser fallback
  -> src/routes/uzg/(uzg).tsx  query(fetchUzgListing)
  -> src/routes/uzg/[file_name].ts  allow-list, range check, download
  -> src/components/Player.tsx + Controls.tsx
```

`src/middleware.ts` wires the `filesystem-routing` API handler. `src/uzg.ts`
(server data/formatting) is not the same layer as `src/routes/uzg/` (pages/API).

## Build and runtime

- `bun run build` emits `dist/client` and `dist/server/server.js`, then runs
  `prerender.ts`, which writes the settled home page to `dist/client/index.html`.
- `bun run start` runs `server.bun.ts`, which imports `dist/server/server.js`.
- `server.bun.ts` serves `/` from the prerendered file with `no-cache`, hashed
  `/assets/*` with `max-age=31536000, immutable`, and `/robots.txt`; everything
  else goes to the SSR handler.
- Docker runs `bun build server.bun.ts` and ships `server.bundle.js` + `dist`.
  The runtime image has no `node_modules`.

## Testing

- Vitest with happy-dom, configured in `vitest.config.ts`; setup is
  `vitest-setup.ts`. Tests sit next to the code as `*.test.ts` / `*.test.tsx`.
- Client code only sees the `src/ftp.ts` contract in `types/ftp.d.ts`. The
  `tsconfig.client.json` program maps `~/ftp.ts` there so browser/server-function
  types never pull in Node or the FTP implementation.

## Images

`@responsive-image/solid` + `@responsive-image/vite-plugin`.

- `?responsive` + `?w=...&format=avif;webp;png&lqip=...` produces responsive sources.
- `?url` returns a plain asset URL.
- `responsiveImage()` in `vite.config.ts` processes both forms.
- Types come from `@responsive-image/vite-plugin/client` (see `tsconfig.json`).
- Home sponsors are collected with `import.meta.glob` in `src/routes/(home).tsx`.

## Gotchas

- FTP credentials are hardcoded in `src/ftp.ts`. The container gets no env.
  `FTP_*` variables in `.env` are not read.
- The FTP cache refreshes at :02 past the hour and serves stale data when the
  host is unreachable, so a transient failure does not blank the listing.
- Completed recordings are immutable: `/uzg/:file_name` responses are cached for
  a year and range requests are answered from the cached listing.
- `isServer` comes from `@solidjs/web` in Solid 2, not `solid-js`.
- Do not debug behavior from hashed bundles in `dist/`; use `dev` or `preview`.
- Solid stack is on stable releases: `solid-js`, `@solidjs/web`,
  `@solidjs/router` and `@solidjs/meta` on 2.x, `@solidjs/vite-plugin` on 3.x.
  `package.json` and `bun.lock` are the source of truth when docs or templates
  disagree about exact patch versions.
